# Paper trading v1 — setup and weekly routine

Three copies of one strategy, each on its own Sim account, trade the same signals with different exits. **Sim accounts only.**

## Files (from this repo)

| File | Copy to (NinjaTrader machine) |
|---|---|
| `ninjascript/NQBotV3Model.cs` | `Documents\NinjaTrader 8\bin\Custom\AddOns\` |
| `ninjascript/NQBotV3Paper.cs` | `Documents\NinjaTrader 8\bin\Custom\Strategies\` |

`MLLorentzianClassification`, `MLExtensionsLib` and `KernelFunctionsLib` must already be installed. They are, wherever v2 runs.

## One-time setup

1. **Copy the two files** above.
2. **Compile.** In NinjaTrader, go to New → NinjaScript Editor and press F5. The Output window must show no errors.
3. **Create three Sim accounts.** In Control Center, open the Accounts tab, right-click and choose Add Simulation Account, and make `Sim-Flat`, `Sim-Vol` and `Sim-Learned`.
4. **Open a chart.**
   - **NQ** (current front month), **15 Second**.
   - Trading hours template: **CME US Index Futures ETH**.
   - Load at least **10 days** of data, because the classifier needs 2,000 bars to warm up.
5. **Add the strategy three times** (chart → Strategies → NQBotV3Paper):

   | Exit Policy | Account |
   |---|---|
   | Flat | Sim-Flat |
   | VolScaled | Sim-Vol |
   | Learned | Sim-Learned |

   - Contracts Per Entry = 1.
   - Max Entries Per Direction = 1 (the v2 setting), unless Matthew confirms otherwise.
   - Ignore Opposite Signal = true.
   - Then enable each one.
6. **Leave NinjaTrader running during RTH** (08:30–15:00 CT). Trades can stay open past 15:00, because there is no forced close.

When a strategy is enabled, it first processes the loaded history. Those trades are logged with `state = historical`, which gives an instant in-NinjaTrader backtest. Only `realtime` rows count as paper results.

## Logs

`C:\ProgramData\nqbotv3\data\paper\paper_<Policy>_<Account>_<start>.csv`, one row per event:
- `signal_taken`
- `signal_skipped` (with the reason)
- `entry_fill`
- `exit_fill`
- `entry_cancelled` / `entry_rejected`

## Weekly

1. Send the CSVs, or link the machine to the Claude chat.
2. Claude reconciles them with the replay engine and the logger.
3. After about 2–3 months of realtime trades, decide which policy, if any, goes live.

## Never

- Don't run this on a funded or live account.
- Don't edit `NQBotV3Model.cs` by hand. It is generated by `model/trees_to_csharp.py` from `model_artifacts/paper_v1/`.
